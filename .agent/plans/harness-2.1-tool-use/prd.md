## 1. Vision
- **One-liner:** Chuẩn hóa Tool Use theo 6 building blocks Lesson 04 — schema validation + approval_mode + error handling + state management — để LLM gọi tool an toàn, không bịa params.
- **Problem:** Tools hiện chỉ có `inputSchema` mô tả, không validate trước khi chạy; không có `approval_mode` phân biệt read/write; không có state history để tránh lặp; lỗi params trả về generic.
- **Target User:** Harness agents (YUNIE, Explore, Plan) + LLM gọi MCP `search_library*` + dev gọi `window.LibrarySearch`.

## 4. Success Metrics
- **Metric 1:** `search_library` với `{}` → lỗi `missing required: query` (không crash)
- **Metric 2:** `search_library` với `{query: 123}` → lỗi `wrong type: query must be string`
- **Metric 3:** `search_library_iterative` với `{query: "hi", top_k: 999}` → clamp `top_k` 1-20, vẫn pass
- **Metric 4:** `get_errors` pass, `tools/list` vẫn 5 tools, `search_library` cũ vẫn 5 hits

## 5. Edge Cases & Constraints
- **Empty query / chỉ stopwords:** validate pass (type ok) nhưng `searchBM25` trả `query rỗng` — giữ behavior cũ
- **Extra params:** ignore (không fail), chỉ validate required + type
- **No enabled books:** không phải lỗi validation, là `gap: no_data` ở RAG loop
- **Constraint:** Node 18+, 0 deps, reuse `STOPWORDS`/`K1`/`B` (minimal-ladder)
- **Persistence · F5 · Scope:** Không lưu `www/`, chỉ validation runtime

## 6. Assumptions
- JSON Schema subset đủ cho v1 (type, required, enum, minimum/maximum, default) — không cần full AJV
- `approval_mode` v1 chỉ `never_require` cho read tools, chưa có write tools để test `always_require`
- History chỉ in-memory (MCP process) + `window._toolHistory` (browser), không persist
